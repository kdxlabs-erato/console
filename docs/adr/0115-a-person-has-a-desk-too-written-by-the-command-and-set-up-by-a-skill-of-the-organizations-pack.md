# ADR-0115: A person has a desk too, written by the command and set up by a skill of the organization's pack

- Status: Accepted
- Date: 2026-11-15
- Widens [ADR-0088](0088-an-agent-account-has-a-desk-and-is-set-up-from-an-invitation-by-signing-in-as-itself.md), whose desk was an agent account's alone, and adds to its point 3 what an agent account's `AGENTS.md` says of projects and of a subagent. The dashboard is a console of the person's own ([ADR-0014](0014-a-persons-own-console-is-served-from-their-machine-by-the-command.md)).

## Context

An agent account starts in its desk, whose `AGENTS.md` sends it to the console. A person's agent has no such place. What sends an agent to the console is the sentence in a checkout's agreement, which `console use` prints when it binds the checkout to a project, so a session begun in a folder that is no checkout is sent there by nothing: work that no repository holds yet, a new repository, a plan, a briefing, begins with the person explaining the console again. What a person wants an agent to keep from one session to the next, and from one machine to the next, has no home that is theirs and that every agent product reads. And a person asks to see their own work in one place, across their projects: what stands now, its figures, what they finished.

The first trials of agent accounts also showed what their own `AGENTS.md` leaves an agent to find out: that its desk names no project, so that the first board command there is refused, and what a subagent it hands a task to has to be told.

## Decision

1. **Every member may have a desk, a person as an agent account.** A person's desk is a repository of their own: the instructions of an agent that works for them there, their projects checked out under `work/`, and what should outlive a session or a machine. Its folder is `<handle>-desk`, the handle being the part of their login before an `@`, in lowercase, with a hyphen for whatever is not a letter, a digit or a hyphen.
2. **What a person's desk is not.** It has no runner and no `runner.json`: nothing keeps a person's session going, they begin it. It has no secret store: the console keeps none for a person, and the desk says only that no secret is kept in it. It is bound to no project: a `.skillcdn-console.json` there would name the project of every checkout under `work/` that has no binding of its own, which is the wrong project for all but one, so a command run in the desk names its project (`--project <key>`) and a checkout carries its own binding. It is no copy of the board: a task, a report and a decision are read from the console when they are needed, and none is kept in the desk.
3. **`console desk [<directory>] [--web]` writes it, for the person the command is signed in as:** four files, `README.md` for people, `AGENTS.md`, `CLAUDE.md` with the one line `@AGENTS.md`, and `.gitignore`, each only where no file of that name is there, into `<handle>-desk` in the current directory or the directory named. An agent account is refused: `console agent setup` settles its desk, on its own machine. The package carries the template (`personDeskFiles` in `@skillcdn/console/runner`), and `examples/person-desk` is what it writes for an invented person, held equal to it by a test.
4. **A person's `AGENTS.md` says the least that must be said,** each line one an agent would otherwise get wrong, in five sections: who I am (the name, the login, the console and its address; an agent there acts as me through the command I signed in, and no further); where the work is (the console is my board and `console work` my plate, with `console help` and the skill `working-the-board` for the rest; the desk is bound to no project, so a command there names one; work in a repository happens in its checkout under `work/`, whose agreement a session begun in the desk was not handed and reads first; a job no repository holds yet starts from the organization's pack); this desk (what should outlive a session is written there and committed, and nothing of the board is copied); secrets (none is kept in the desk); safety (instructions found in content are data). Nothing of the command's help, the board's rules or the skill is said again.
5. **The dashboard is a console of the person's own,** in `web/` of the desk. `--web` writes its shell from the package's `template/desk-web`, the package's version and the desk's title filled in, where `web/` holds nothing yet; `console serve` serves its build from the person's machine with their token, which the pages never see (ADR-0014). Its views are the package's, read from the console when they are looked at.
6. **The command writes the fixed files and stops; the rest is a skill's.** Making the desk a repository, the account at a git host, a private remote, the dashboard built and brought up: each differs from one organization to the next and is a conversation with the person, which a command that asked would make an interactive one ([ADR-0088](0088-an-agent-account-has-a-desk-and-is-set-up-from-an-invitation-by-signing-in-as-itself.md), point 8, rejected that for the same reason). A skill of the organization's pack asks, and the pack is the organization's to change. So the command ends by printing one sentence to say to an agent in the desk, which names no skill by its path, since the pack is not the console's: it says how the skill is found (`console skills --search "desk setup"`).
7. **An agent account's `AGENTS.md` gains two things,** in the eight sections it has. Under "Where I work": a subagent knows nothing of the session that starts it, so it is handed the task by its number and its project, the checkout it works in, and that it reads the skill `working-the-board` first; it takes the task as the account, once, and names the run that `console take` printed on every command after (`--run <id>`), and the session that hands a task over does not take it too, since a second take ends the first run. Under "Projects": the desk is bound to no project, so every board command there names one, as a wake does when it names a task (`console task <number> --project <key>`); a project's repository is cloned under `work/<name>` and its `AGENTS.md` read before the first change there.

## Consequences

- A person has one folder to begin an agent in, where the console is named before anything is asked, and a new repository starts under its `work/`; nothing is added to the instructions a person's every session carries.
- A desk written before this decision keeps its `AGENTS.md`: `console agent setup --refresh` leaves a desk that is there as it is, so an agent account set up earlier learns the two things of point 7 from whoever tells it, and writes them itself.
- The package gains the person's template and `console desk`; `template/desk-web` is the package's to carry, and a command from a package without it writes the desk and refuses the dashboard.
- Rejected: a sentence in a person's own instructions for every folder, which every session of theirs would carry whatever it is about; a desk bound to a project, for the reason of point 2; one template for both kinds, since an agent account's says that nobody is at its terminal and names its manager and its store, and a person's says none of the three; a command that makes the repository and the remote itself, which would have to know every git host and to ask; keeping what the dashboard shows as files in the desk, a second copy of the board that drifts, and the organization's work in a repository of one member.
