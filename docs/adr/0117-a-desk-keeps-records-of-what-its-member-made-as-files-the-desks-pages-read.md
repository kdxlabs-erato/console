# ADR-0117: A desk keeps records of what its member made, as files the desk's pages read

- Status: Accepted
- Date: 2026-11-15
- Adds to [ADR-0115](0115-a-person-has-a-desk-too-written-by-the-command-and-set-up-by-a-skill-of-the-organizations-pack.md) and [ADR-0116](0116-a-desks-dashboard-is-a-page-of-a-console-of-ones-own-read-as-it-is-looked-at.md), which stand as written: where the first said that a desk is no copy of the board and the second that nothing of the board is kept, this decision makes neither a rule (point 7), and where the first named a person's desk `<handle>-desk`, it is named as an agent account's (point 1). An agent account's desk is [ADR-0088](0088-an-agent-account-has-a-desk-and-is-set-up-from-an-invitation-by-signing-in-as-itself.md)'s; the serving is [ADR-0014](0014-a-persons-own-console-is-served-from-their-machine-by-the-command.md)'s.

## Context

The first desks held instructions and, for a person, a page of their own work read from the board. That is the smaller half of what a desk is for. A member wants one place where what they made is kept and followed: the creatives made for an ad, whether each was used, how the ads did; the documents written; the results handed over. The board does not hold that: it holds the work to do and the record of doing it, a task at a time and a project at a time, and what was made is of many kinds, outlives its task, and is the member's own.

A desk is a repository that a member, a person or an agent account, makes at their own account at the git host, `<account>/desk`, and uses as wholly their own. Being a repository of one's own, it keeps files as they are, the large ones with git LFS. What a member's console shows of it is that member's own extension of the console's pages.

## Decision

1. **The words, and the name.** A *desk* is a member's own repository, private, wholly theirs. A person's is named as an agent account's is: the repository is `<account>/desk` at the member's own git account and the folder is `desk`, so `console desk` with no directory named makes `desk` in the current directory; a git host that gives an account no place of its own keeps the name its module gives. *The desk's pages* are the member's own extension of the console's pages: a console of their own, served from their machine, with the pages the desk adds. *Records* are what a desk keeps. The documents say these; "dashboard" is a word a person may say.
2. **A desk keeps records under `records/`, as files** ([specs/records.md](../specs/records.md)): an index of collections; for each collection what it is and how its items are read (its statuses, fields, metrics and the ratios worked out from them), the items that were made, where each was used, and how each did by day; and under `files/` the files themselves. An item names its preview, its files, where it is elsewhere and, where its member ties it to one, a task of the board.
3. **JSON that an agent writes, and the files as they are.** Whoever works in a desk is an agent with file tools: it writes a record as it writes any file, git shows what changed, and nothing is generated or built. The format is small enough to be said in one file of the desk, `records/README.md`, and its schemas are the package's (`@skillcdn/console/api`), which the pages parse with. A file under `files/` has no bound and is of any kind; a JSON file has one, since a page reads it whole.
4. **The command writes the format, and no collection.** `records/README.md` is a fixed file of both desks, written with the desk by `console desk` and `console agent setup`: an agent account records what it made too. No command makes an index or a collection: the first record does. Which kinds a desk keeps is said by the desk's own `AGENTS.md`, written at its setting-up from what the member said and theirs to change; a skill of the pack run in a desk follows it, and none carries a recording step of its own.
5. **`console desk check` says whether the records read right,** with no page and no console: each problem with its file and what is wrong, an exit of 1 with any, and a file that git LFS has not fetched as a note. An agent that wrote a record runs it.
6. **`console serve --records <dir>` serves what a desk keeps** at `/records/`, beside the build and the API, on the loopback alone: read at each request and never kept by the browser; `GET` alone; nothing outside the directory, no file whose name begins with a full stop, no listing; a picture, a video, a sound and a PDF by their kinds, so that a page shows them in place, and anything else as a download; a part of a file where one is asked for, so that a video plays; and a file that is an LFS pointer refused by name. The build's own policy already shows what is of its origin, so nothing of it is widened.
7. **Work in a desk is its member's own, and tying a desk to the board is free.** Nothing done in a desk for its member, its setting-up, a record, a page, is a task unless the member puts it on the board, and work that should be done on the board is put there by whoever needs it. Nothing proposes that a record be tied to a task, and nothing forbids keeping something of the board in a desk or reading the board from the desk's pages: the templates say neither. What an organization wants kept out of its members' own repositories, it says in its rules. What stays a rule of every desk: no secret is kept in it, and its repository is private.
8. **Both `AGENTS.md` files say this in lines, and lose what an agent knows anyway.** Each gains: that what was made and should be found again is kept under `records/`, as its README says, with the kinds the member keeps named there; that work in the desk is the member's own and on no board unless they put it there; that the skill `working-the-board` is read before the first task of the board, and not for a job that is no task; and that the desk is never bound to a project (`console use` is for a checkout). A person's says which language to write to them in, where the console knows it. An agent account's says that the organization's pack is looked in before a job is done by hand, that a brief names a task and does not restate it, and that scratch files go under `work/`. Each loses the lines these make redundant, and the person's the sentence that kept the board out.

## Consequences

- What a member made is found again in one place, with what became of it, in a repository that is theirs; the board keeps holding the work, and neither is a copy of the other.
- The format is a contract the package keeps: `records/README.md` in every desk, the schemas, the check and the serving change together, and a page built on an older package reads past what a newer format adds.
- A desk that keeps large files needs git LFS at its git host, which its member sets up; a machine that has not fetched them shows the records and says which files are not there yet.
- An agent account has the records and the check, and no pages: a manager who wants to see them serves the desk's records from a checkout of the desk.
- Rejected: records on the board, as documents of a project or a plugin's collections, since what was made is not a project's and a member's own repository needs no permission model; a command that writes a record, which would need a flag for every field and freeze a format that an agent writes well from one page; a database or a generated site in the desk, which needs a build to read a file; bounding the files or keeping large media elsewhere and linking it, since a repository of one's own with LFS holds them; serving an SVG as a document of the pages' origin, where a script in it would act with the member's standing.
