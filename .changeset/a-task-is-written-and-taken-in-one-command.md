`console task new <title> ... --take [--rules <mark>] [--agent <name>]` writes a task and takes it, in that order, in one command: it prints what `task new` prints, the number first, and then what `console take` prints, with `--rules` and `--agent` as `take` has them; `--json` carries what a take answers with the task as it was written beside it (`written`). It is for work a person gives in chat, which is written and taken at once: a session that sends its commands together could not read the number between the two, on a board where another agent writes too. With `--take` the task is written `ready` where no state is said; a state that cannot be taken (`done`, `dropped`) is refused before anything is written, and so are `--rules` and `--agent` without `--take`. Where the take fails after the task was written, the command says so with the number, `console take <number>` being the way on, so that no second task is written; where the run began and only the reading of what a take prints failed, it says that the task is taken and by which run. The skill `working-the-board` (1.36) uses it for work given in chat. Without `--take`, `task new` is as it was.
