`console login` keeps nothing its credentials file would not read back.

- What an address answered to begin a connection was kept as it came where the call ends before the approval, as under an agent. An answer beyond what the file reads (a wait over ten minutes, an empty code, a secret or a page's address too long) left a file the command could not read again, and every later command stopped on it, at every console signed in on the machine, until the file was moved away. The command now holds what it is about to keep to the file's own bounds, the connection that waits and the login a token becomes alike: where an answer is beyond them it says that the address answered what it cannot keep and stops with `1`, with nothing written, no code shown and no token given up for it. The file is never written in a shape it would not read back.
- `restConnectionSchema`, what `POST /api/v1/connect` answers, is bounded no wider: the code up to 64 characters, the page's address up to `MAX_URL_LENGTH`, the secret up to `MAX_SECRET_LENGTH`, the instant up to 40 characters, the wait up to 600 seconds, none empty. A console answers a code of nine characters, a secret of some fifty and a wait of three seconds, so nothing changes for one; an answer beyond the bounds is refused as `invalid_response`.
