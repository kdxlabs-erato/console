Breaking: `console login` under an agent says its code at once, and a script that ran it with no terminal and waited in that one call for the approval now passes `--wait <seconds>` to wait there. Where no terminal shows the command's words as they are printed, as under an agent, whose host shows them when the command ends, the call that begins a connection prints the address and the code, with the line that says to tell the person both and to run the same command once more, and ends at once; the next `console login` for that console begins no new code and waits for the approval, ninety seconds a call, ending with exit code `3` and the words to wait on while the code lasts. `--wait <seconds>` says another wait for either call. At a terminal the command waits where it stands, as before. The connection that waits is kept in the credentials file while its code lasts and is never printed: `console logins` names its code, `console logout` forgets it. Nothing new is asked of the console, so a console from before this version is connected to the same way. A script that ran `console login` with no terminal and waited on it now says `--wait <seconds>`; `--token-stdin` is unchanged. The Agents page and the Connect page tell an agent to run the commands and do what each says.
