`console-plugin check` reads a file of a plugin's package up to 4 MiB, and in a time that grows with its size. It read every file whole, whatever it weighed, and three of its readers tried again from every place they could have begun: a stylesheet of 240 KB of comments never closed took seconds and one of some megabytes minutes, as did a script with an `import` followed by nothing but blanks, and a name in the console's prefix of 8 MB ended the check on an error of the runtime's. A file beyond the bound, a manifest, the server module, a script or a stylesheet of the web bundle or a skill, is now a problem said by its size, `<file> is <n> bytes: the check reads a file of up to 4 MiB (4194304 bytes) whole, and did not read this one`, and is not read, the server module not loaded either; `console-plugin help` says the bound. A plugin's files are a fraction of it, the example's server module under 1 MiB. The stylesheet's comments, the names in the console's prefix and the imports of a bundle, `forbiddenImportsIn` of `@skillcdn/console/plugin` among them, are read once from end to end and find what they found, with one difference a browser makes too: a comment opened and never closed takes the rest of the stylesheet with it, where its classes were read before.
