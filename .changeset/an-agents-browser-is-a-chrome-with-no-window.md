Breaking: an agent account's browser is a Google Chrome with no window, unless its desk names the product's own browser tool ([ADR-0151](https://github.com/skillcdn/console/blob/main/docs/adr/0151-an-agents-browser-is-a-chrome-with-no-window-unless-its-desk-names-the-products-own.md)).

- **`runner.json` takes `"browser": "headless"`, and means it where it names no browser.** The `claude` driver starts Claude Code with the program that drives a headless Chrome, `chrome-devtools-mcp`, as a server of its own for that run (`--mcp-config`), with no window, with its usage statistics off and with the headers a sign-in is carried in left out of what its tools answer. Such a browser needs no screen, no extension and no sign-in of its own, and keeps a profile in the OS account's home, so that a sign-in stays from one session to the next. The program is installed on the machine, `npm install -g chrome-devtools-mcp`; the package neither carries it nor fetches it.
- **A desk that is there and names no browser changes.** It was started with no browser, and is started with a headless one from its runner's next start. Install the program on its machine, beside Google Chrome: until it is there, Claude Code says that the server failed and the session goes on with no browser, as before, and the session's record says so, with what installs the program (it runs on Node.js 20.19, 22.12 or later). A desk that is to have none names `"browser": "none"`, which `--no-browser` now writes. A desk that names `"browser": "chrome"` starts Claude Code with `--chrome` as it did.
- **`"browser": "window"` is the same browser with its window**, the same program and profile started without `--headless`, for when someone is to see an agent's browser or to act in it. An agent names it in its own `runner.json` and names `"headless"` again after; the runner takes each change between two turns. Not seen run.
- **`console agent setup` looks for a headless browser unless told otherwise**: Google Chrome where that program looks for it, and the program, each said with what installs it where it is missing. A setup that went on with Chrome alone now asks for the program too. `--browser chrome` looks for Claude Code's own browser tool, as before, and `--no-browser` for none. A new desk names what was looked for and found, and a desk whose driver starts its product with no browser (`codex`, `acp`) names none.
- **The guide, an account's first task and the skill `running-an-agent`** say what each browser is. Which an agent uses is its own to choose, by the name in its `runner.json`, and they say that the browsers are the `claude` driver's. They no longer set a sign-in aside for a person, to be made over a remote desktop in the agent's own browser: a headless one has no window for it, and an agent asks for help where it cannot go on, as with anything else.

For a driver of your own, `DriverHost` gains `platform`, the system the runner is on, and `RunnerConfig.browser` is always a name. The `codex` and `acp` drivers start their products with no browser yet. Seen run on a Mac by hand, with Claude Code 2.1.330 and the program at 1.13.0; not run on Windows or on Linux.
