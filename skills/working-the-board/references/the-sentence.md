# The sentence a repository carries

A repository whose checkouts are worked through a console says so in its agreement (AGENTS.md, or CLAUDE.md where that is the file agents read), in one sentence copied as it is and placed at the head of its workflow; a pack says it in the rules of its `SKILLCDN.md`, with `the checkout` for `this checkout`. The sentence has an agent run `console whoami` before its first step, which changes nothing on the board, says who acts at which console in which project, and is refused where the checkout is bound to a project that console does not have; it binds the checkout to the console and says nothing more of how: what `console whoami` answers names what is read before the first task, the rules and the skill working-the-board, and the repository's own agreement keeps saying how a change is committed and pushed. `console use` prints the sentence after binding a directory, so that whoever sets a checkout up, a person or an agent, copies it from there; a checkout that carries a sentence of before, the one that named the two conditions and no command or the one that ended on `console help`, stays right, and takes this one when its agreement is next changed. The file it writes, `.skillcdn-console.json`, names the project and the console's address, so that every clone works at the same console whatever its machine's default login is; it names an account only where `--account` asked for one, and never a token. A private repository commits it; a public one leaves it out, and each checkout is bound once with `console use <key>`. An agreement that also names the project's key gives `console whoami` something to be held against that the binding did not write; a public repository whose board is not public leaves the key out.

> **Bound to a console?** Before the first step, run `console whoami`: when it names a project, or `.skillcdn-console.json` is in this checkout, work the task through that SkillCDN console (its answer says how).
