# The sentence a repository carries

A repository whose checkouts are worked through a console says so in its agreement (AGENTS.md, or CLAUDE.md where that is the file agents read), in one sentence copied as it is and placed at the head of its workflow; a pack says it in the rules of its `SKILLCDN.md`, with `the checkout` for `this checkout`. The sentence binds the checkout to the console and says nothing of how: the command's help and the skill working-the-board say how, and the repository's own agreement keeps saying how a change is committed and pushed. `console use` prints the sentence after binding a directory, so that whoever sets a checkout up, a person or an agent, copies it from there. The file it writes, `.skillcdn-console.json`, names the project and the console's address, so that every clone works at the same console whatever its machine's default login is; it names an account only where `--account` asked for one, and never a token. A private repository commits it; a public one leaves it out, and each checkout is bound once with `console use <key>`. An agreement that also names the project's key gives `console whoami` something to be held against that the binding did not write; a public repository whose board is not public leaves the key out.

> **Bound to a console?** When `.skillcdn-console.json` is in this checkout, or `console whoami` names a project, work the task through that SkillCDN console (`console help` says how).
